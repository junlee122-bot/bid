# BID SHIELD 모델 검증 계획

## 0. 현재 상태를 먼저 명확히 합니다

현재 저장소의 BID SHIELD는 **학습된 부도예측·신용평가 모델이 아닙니다.**

- 기준 위험점수는 공개된 규칙의 합입니다.
- Monte Carlo는 사용자가 확인할 수 있는 분포 가정에서 원가·지급지연·금리·물량 충격을 표본화합니다.
- 화면의 “현금부족 표본비율”은 반복 표본 중 현금부족이 발생한 비율입니다.
- P90 필요자금은 그 가정분포에서 필요자금 표본의 90백분위입니다.
- 이 수치들은 실제 부도율, 연체확률, 대출 승인확률, 신용등급 전이확률 또는 미래 성과 보장이 아닙니다.

따라서 현 버전의 적절한 용도는 계약조건·원가·지급지연에 대한 **시나리오 분석, 자료 보강 우선순위, 자금계획 회의 지원**입니다. 자동 승인·거절이나 신용한도 결정에 사용해서는 안 됩니다.

이 문서는 KO-DLab 등에서 적법하게 사용할 수 있는 실데이터가 확보된 뒤 모델을 학습·보정·검증하는 사전 계획입니다. 실제 제공 필드와 표본 수를 확인하기 전에는 학습 성능을 주장하지 않습니다.

## 1. 검증 질문

| 영역 | 검증 질문 |
| --- | --- |
| 데이터 | 의사결정 시점 이전에 알 수 있었던 기업·계약정보만 사용했는가 |
| 현금흐름 | 월별 유입·유출과 최저현금·필요자금이 실제 기성·입금·원가·잔액을 허용 오차 안에서 재현하는가 |
| 순위 | 높은 위험 신호가 이후 관측된 유동성 사건을 더 자주 포함하는가 |
| 보정 | “10%”라고 표시한 값이 독립 표본에서 약 10% 발생하는가 |
| P90 | 제시한 P90 필요자금이 독립 표본의 실제 최대 자금공백을 약 90% 포괄하는가 |
| 안정성 | 시점·업종·규모·조달유형이 달라도 성능 저하와 편향이 허용범위인가 |
| 행동가치 | 기존 업무규칙과 같은 예산에서 더 많은 실제 고위험 계약을 조기에 검토하는가 |

## 2. 분석 단위와 시간축

### 권장 관측 단위

`기업키 × 계약키 × 분석기준일`의 스냅샷을 기본 단위로 합니다. 한 계약에 월별 스냅샷이 여러 개면 같은 계약과 기업이 train·holdout에 섞이지 않도록 그룹을 유지합니다.

### 시점 정합성

특징값은 분석기준일 `t0`에 이용 가능했던 값만 사용합니다.

- 재무정보는 공시·입수 가능일과 결산 기준일을 둘 다 보존합니다.
- 낙찰·계약·변경·검수·입금 사건은 실제 발생·등록시각을 보존합니다.
- `t0` 이후의 지급지연, 변경계약, 부실상태, 실제 원가를 입력 특징에 넣지 않습니다.
- 동일 기업의 미래 계약 outcome이 과거 행에 역으로 유입되지 않도록 point-in-time join을 사용합니다.

### 관측창

계약 시작 또는 분석기준일부터 3·6·12개월을 별도 outcome 창으로 만듭니다. 현재 UI의 12개월 계획과 직접 대응하는 주 평가는 12개월이며, 3·6개월은 조기경보 성능을 봅니다. 계약이 끝나기 전 데이터가 끊긴 행은 단순 정상으로 처리하지 않고 검열 사유를 기록합니다.

## 3. outcome 정의

실제 KO-DLab 제공 필드를 확인한 뒤 아래 우선순위로 라벨을 확정하고 데이터 사전에 버전 고정합니다.

### 3.1 주 outcome: 관측 유동성 사건

다음 중 하나가 관측창 안에 발생하면 1, 모두 관측되고 발생하지 않으면 0으로 정의하는 안을 우선 검토합니다.

1. 계약 관련 실제 최대 현금공백이 0원 초과
2. 약정 지급 또는 채무상환의 30일 이상 연체
3. 보증사고, 대위변제, 채무불이행, 회생·파산 등 명시적 사건
4. 운영자금 부족으로 확인된 계약 중단·해지

서로 성격이 다른 사건을 하나로 합치기 전에 발생률·기록 신뢰도·업무 목적을 검토합니다. 가능하면 “현금공백”, “30일 이상 연체”, “중대 부실”을 별도 라벨로도 평가합니다. 제공 데이터에 없는 항목은 추정해 라벨링하지 않습니다.

### 3.2 연속 outcome

- 실제 12개월 최대 자금공백(원)
- 실제 최저현금잔액(원)
- 실제 지급지연일
- 실제 계약 원가상승률
- 실제 생존마진(원·%)

명목금액뿐 아니라 매출·계약금액 대비 비율과 로그 변환을 함께 검토합니다.

### 3.3 라벨 품질 등급

| 등급 | 조건 | 사용 |
| --- | --- | --- |
| A | 금융거래·지급·원가 원장과 사건일이 직접 확인됨 | 주 학습·검증 |
| B | 기관 확인 문서 또는 정합한 다중 출처 | 보조 학습, 별도 민감도 |
| C | 단일 설문·추정·누락 보정 | 학습 제외, 탐색 분석만 |

라벨 정의와 창을 결과를 본 뒤 바꾸지 않습니다. 변경 시 새 버전으로 재등록하고 이전 결과도 보존합니다.

## 4. 입력 특징과 누수 방지

### 현재 바로 매핑 가능한 특징

- 기업: 연매출, 영업이익, 현금성자산, 유동자산·부채, 총부채, 수주잔고, 평균 회수·지급일, 업종, 규모
- 조달: 자원·업무, 기초·추정·낙찰·계약금액, 낙찰률, 기관, 계약방법, 생애주기
- 계약 가정/증빙: 원가율, 기간, 지급방식·지연, 선금·유보·보증·초기투입·고정원가, 운영비, 상환액, 금리
- 파생: 유동비율, 순운전자본, 부채/매출, 수주잔고/매출, 12개월 현금흐름, 생존마진, 최저현금, 위험 기여도

### 금지할 누수

- outcome 창 안에서 발생한 실제 입금·연체·원가를 `t0` 특징에 사용
- 계약 종료 후 확정된 최종 계약금액·최종 원가를 최초 심사 특징으로 사용
- 같은 기업·계약의 중복 행을 train과 holdout에 분할
- 전체 기간 통계로 범주 인코딩·결측 대치한 뒤 split
- 라벨 또는 미래 사건에서 파생된 데이터 품질·수동검토 결과 사용

모든 전처리·대치·스케일링·인코딩은 train 안에서 적합하고 validation/holdout에는 변환만 적용합니다.

## 5. 데이터 분할

무작위 80/20 한 번으로 끝내지 않습니다.

1. **개발 train**: 가장 오래된 기간 약 60%
2. **시간 validation**: 그다음 기간 약 20%, 특징·하이퍼파라미터·캘리브레이션 선택
3. **동결 holdout**: 가장 최근 기간 약 20%, 최종 1회 평가
4. **외부/전향 검증**: 가능하면 다른 기관·업종 또는 이후 3~6개월 자료

기간 비율은 실제 건수와 사건 수에 따라 조정하되 날짜 경계는 먼저 고정합니다. 같은 `stable company key`가 여러 기간에 걸치면 더 엄격한 검증에서는 기업 단위 group holdout을 추가합니다. 공동수급·계열 관계가 식별되면 같은 그룹으로 묶습니다.

각 평가 셀에는 최소 사건 수를 함께 표시합니다. 사건이 30건 미만인 세부집단은 단정적 성능 비교 대신 신뢰구간과 “표본 부족”을 표시합니다.

## 6. 학습·보정 전략

### 6.1 기준선

복잡한 모델보다 먼저 다음 기준선을 동결합니다.

1. 현 규칙 기반 위험점수
2. 현금·유동비율·부채/매출 등 소수 변수의 로지스틱 회귀
3. 기관의 기존 수동 규칙이 있으면 그 결과

새 모델은 기준선 대비 개선과 설명 가능성을 함께 보여야 합니다.

### 6.2 후보 모델

- 사건 분류: 정규화 로지스틱 회귀와 제약을 둔 gradient-boosted trees 비교
- 자금공백: robust/quantile regression으로 P50·P90 직접 추정 후보
- 지급지연: 검열이 많다면 survival model 후보

표본이 작거나 데이터 정의가 불안정하면 복잡한 모델을 채택하지 않습니다. 하이퍼파라미터 탐색 범위와 선택 기준은 validation을 보기 전에 기록합니다.

### 6.3 확률 보정

분류모형의 원 점수는 확률로 바로 표시하지 않습니다.

- validation에서 Platt scaling과 isotonic regression을 비교
- 사건 수가 적으면 과적합 위험이 낮은 Platt를 우선
- 선택한 보정기를 train+validation 규칙으로 고정한 뒤 holdout에 한 번 적용
- 보정 전·후 Brier score, log loss, ECE, calibration intercept/slope, reliability plot 보고

표본비율을 “예측확률”로 이름 바꾸려면 독립 holdout의 보정 수용기준을 통과해야 합니다.

### 6.4 Monte Carlo 분포 보정

실제 원가상승·지급지연·금리·물량 변화의 `t0` 대비 잔차를 train에서 산출합니다.

1. 극단값은 삭제보다 데이터 오류와 실제 극단사건을 분리
2. 중앙·꼬리 적합도를 비교해 정규, t, 경험분포/부트스트랩 후보 평가
3. Pearson뿐 아니라 rank correlation과 tail 동시발생을 확인
4. 업종·계약유형·기업규모별 표본이 충분할 때만 조건부 분포 사용
5. 경계·상관·불확실성 배수를 train에서 적합하고 validation에서 선택
6. holdout에서 P50·P90 자금공백 coverage와 interval width 평가

현재 0.45/0.35/0.55/-0.25 loading은 학습값이 아니므로 실데이터 보정 후 모델 버전을 올리고 이전 버전과 결과를 재현 가능하게 보존합니다.

## 7. 평가 지표

### 분류

- 사건률과 혼동행렬
- PR-AUC(희소 사건의 주 지표), ROC-AUC(보조)
- top 5%·10%·20% recall/precision/lift
- Brier score, log loss
- ECE(10개 등빈도 bin), 최대 calibration error
- calibration intercept와 slope, 95% bootstrap 신뢰구간

### 연속값·분위수

- MAE와 median absolute error
- 금액가중 MAE와 계약금액 대비 절대오차
- P50 pinball loss
- P90 pinball loss와 경험적 coverage
- 업종·규모·계약유형별 오차와 과소추정률

### 의사결정 가치

동일한 가용예산 또는 동일한 검토건수에서 다음을 비교합니다.

- 실제 사건 계약의 조기 포착 수
- 실제 최대 자금공백 커버율
- 불필요 검토 수와 미탐지 수
- 배분 1원당 실제 고위험 공백 커버 금액

“우선순위 가중 완화율”은 모델 내부 지수이므로 실제 손실 감소로 해석하지 않고, 별도의 outcome 기반 효과를 측정합니다.

## 8. 사전 수용기준

아래는 최초 운영 후보를 검토하기 위한 기준입니다. 데이터 품질·업무 비용에 따라 모델 심의에서 더 엄격하게 조정할 수 있지만 holdout 결과를 본 뒤 완화하지 않습니다.

### 데이터 게이트

- 주 outcome 라벨 A/B 비율 90% 이상
- 핵심 필드(계약키, 기업키, 기준일, 계약금액, outcome/사건일) 완전성 95% 이상
- 날짜 역전·중복·미래 누수 오류 0건
- holdout 주 사건 최소 100건 권장; 50건 미만이면 운영확률 표기를 보류

### 현금흐름·P90

- holdout P90 경험 coverage 85~95%
- 주요 업종·규모 중 사건 30건 이상 셀의 P90 coverage 80% 미만 없음
- P90 과소추정 계약 비율과 최대 과소금액을 별도 공개
- 기준선 대비 P90 pinball loss 5% 이상 개선 또는 더 단순한 기준선 유지

### 분류·보정

- holdout PR-AUC가 사건률 기준선보다 유의하게 높고 bootstrap 95% CI 하한이 기준선 초과
- Brier score가 보정 전과 규칙 기반 기준선보다 악화하지 않음
- calibration slope 0.8~1.2, intercept -0.1~0.1 권장
- ECE 0.05 이하, 최대 calibration error 0.10 이하
- top 10% lift 2.0 이상을 목표로 하되 신뢰구간 함께 보고

### 안정성·형평

- 주요 업종·규모·조달유형의 PR-AUC/recall 차이를 전체 대비 절대 0.10 이내로 목표
- top 10% recall의 집단 간 최대 격차 15%p 초과 시 원인·완화·업무 타당성 심의
- 합법적·업무상 필요한 특징만 사용하고 보호속성·대리변수 위험을 별도 검토

기준 하나를 통과했다고 자동 운영하지 않습니다. 데이터 게이트, 성능, 보정, 안정성, 업무검토와 보안·법무 승인을 모두 충족해야 합니다.

## 9. 백테스트

### 롤링 시간 백테스트

최소 3개 기준일에서 다음 절차를 반복합니다.

1. 기준일 이전 자료만으로 학습·보정
2. 다음 3·6·12개월 outcome 예측
3. 당시 사용 가능했던 계약조건과 재무정보로 현금흐름 재생성
4. 분위수 coverage, calibration, top-k lift, 배분 결과 기록

각 창에서 모델 버전·데이터 스냅샷·코드 커밋·시드·분포를 보존합니다.

### 챌린저 비교

- 현 규칙 기반 엔진
- 보정된 단순모형
- 후보 고급모형

성능이 비슷하면 더 단순하고 설명 가능한 모델을 채택합니다. 챌린저의 개선이 특정 시기·기관 하나에만 의존하는지 확인합니다.

## 10. 민감도·스트레스 검증

### 수학적·업무 방향성

- 원가상승·지급지연·금리상승이 커질 때 자금공백이 비정상적으로 감소하지 않는지
- 선금 증가·지급지연 감소가 유동성을 악화시키는 역전이 없는지
- 생존마진 음수 계약이 기본 `viable-only` 자동배분에 포함되지 않는지
- 예산 증가 시 총 배분액·커버리지가 감소하지 않는지

비선형 지급시점 때문에 국소적인 계단 변화는 허용하되 원인을 설명합니다.

### 가정 민감도

- 분포 표준편차 0.8·1.0·1.35배
- 상관 loading ±0.1
- 원가·지연 경계 확대/축소
- 기업 재무 기준일 6·12·18개월 경과
- 원가율 ±5%p, 회수일 ±30일, 운영비 ±20%

순위·P90·배분이 작은 입력 변화에 과도하게 뒤집히는 계약을 “불안정”으로 표시하고 수동 검토합니다.

### 결측 민감도

완전 사례, 보수 대치, 다중대치 후보의 결과를 비교합니다. 결측 자체가 위험 신호일 수 있으므로 결측 지시자를 평가하되 데이터 수집 프로세스의 대리변수가 되는지 확인합니다.

## 11. 드리프트 모니터링

운영 후보가 승인되면 월별 모니터링, 분기별 심층 검증을 권장합니다.

| 감시 대상 | 경고 | 중대 조치 |
| --- | --- | --- |
| 수치 특징 PSI | 0.10 이상 | 0.25 이상 |
| 범주 분포 total variation | 0.10 이상 | 0.20 이상 |
| 결측률 | 기준 대비 +5%p | +10%p |
| 사건률 | 예상구간 이탈 | 2개월 연속 이탈 |
| P90 coverage | 85~95% 밖 | 80% 미만 |
| ECE | 0.05 초과 | 0.10 초과 |
| calibration slope | 0.8~1.2 밖 | 0.7 미만 또는 1.3 초과 |

PSI만으로 결정하지 않고 Wasserstein/KS, 범주 변화, 업무 정책·금리·조달제도 변경을 함께 봅니다. 중대 조치 시 확률 표기를 중단하고 규칙 기반 시나리오 모드로 강등한 뒤 재보정 또는 재학습합니다.

## 12. 검증 산출물과 거버넌스

모델 버전마다 다음을 보존합니다.

- 데이터 사전, 출처·권리·기준일, 라벨 정의와 제외 사유
- train/validation/holdout 기간과 기업·계약 그룹 규칙
- 전처리, 특징 목록, 하이퍼파라미터, 보정기
- 코드 커밋, 패키지 잠금, 난수 시드
- 전체·세부집단 성능, 신뢰구간, calibration·coverage plot
- 실패 사례, 민감도, 드리프트 기준, 사용 제한
- 모델 승인자, 승인일, 재검증일, 롤백 버전

의사결정실 JSON 스키마는 `decisionModelVersion`, `calibrationVersion`, `dataSnapshotId`, `validationStatus`를 기록합니다. 현재는 검증 전 상태를 명시하기 위해 `scenario-only-unvalidated`와 `null` 보정·스냅샷 식별자를 내보냅니다. KO-DLab 검증 시 실제 보정 버전과 동결 데이터 스냅샷 ID로 교체하며, 검증 미통과 버전은 “가정 기반 표본비율”만 표시하고 “예측확률”이라는 용어를 사용하지 않습니다.

## 13. KO-DLab 확보 직후 실행 체크리스트

1. 제공 필드·기간·단위·갱신주기·반출 제한을 확인하고 [KODATA_FIELD_MAP.md](KODATA_FIELD_MAP.md)를 실제 컬럼명으로 갱신
2. 기업키·계약키·사건키의 1:N 관계와 point-in-time join 검증
3. outcome 후보별 발생률·누락·기록지연 탐색
4. 라벨·관측창·분할일·수용기준을 동결
5. 현 규칙 기반 엔진을 변경 없이 baseline으로 백테스트
6. 분포 보정과 단순모형부터 개발
7. validation에서 선택한 뒤 holdout 1회 평가
8. 미통과 시 확률 표기 없이 시나리오 모드 유지
9. 통과 시에도 사람의 승인·증빙 게이트와 롤백 절차를 먼저 구축

이 순서를 지키면 공모전 시연 수치를 과장하지 않으면서, 실데이터가 주어졌을 때 무엇을 어떻게 검증할지 재현 가능한 연구계획으로 제시할 수 있습니다.
