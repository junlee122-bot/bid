# BID SHIELD 아키텍처

## 설계 원칙

1. **계산과 화면 분리**: 분석 함수는 React·Next.js·네트워크에 의존하지 않는 순수 함수다.
2. **키 없는 완전 실행**: 합성 데이터만으로 모든 핵심 화면과 시나리오가 작동한다.
3. **서버 전용 인증키**: 공공데이터 인증키는 Route Handler 내부에서만 사용한다.
4. **가정의 가시성**: 숫자와 함께 기준일, 데이터 품질, 시나리오 가정을 표시한다.
5. **실패를 숨기지 않음**: API 오류와 CSV 행 오류를 구조화하고 데모 대체 여부를 명시한다.

## 데이터 흐름

```text
나라장터 API ─┐
KODATA형 CSV ─┼─> 정규화·검증 ─> ContractRecord ─> 분석 엔진 ─> 화면·JSON
합성 데이터 ──┘                         │
                                         └─> 브라우저 워크스페이스 저장
```

## 분석 계층

- `domain.ts`: 화폐·비율 단위와 입력·출력 계약
- `analytics/analysis.ts`: 지급일정·월별 현금흐름·위험요인별 점수와 설명
- `analytics/portfolio.ts`: 계약 분석의 합산·집중도·포트폴리오 현금흐름
- `analytics/financing.ts`: 자금부족·회수시점 기반 금융구조
- `analytics/index.ts`: 계약·포트폴리오·시나리오 공개 API

금액은 모두 KRW 숫자, 비율은 퍼센트포인트로 통일하고 필드별 현실적 상한을 적용한다. 공개 함수는 NaN·무한대·0 나누기를 방지하고 입력을 변형하지 않는다.

### 현금흐름과 금융추천 불변조건

- 계약 수행기간 입력은 1~120개월, 기본 지급지연과 시나리오 반영 유효 지급지연은 0~730일을 지원한다. 예측기간은 계약 길이와 무관하게 12개월이며 일 단위 지급지연은 보수적으로 월 단위 올림 처리한다.
- 선금은 1개월 차 유입, 유보금은 준공 지급보다 1개월 뒤 유입, 계약보증 예치금은 1개월 차 유출 후 수행기간과 지급지연이 끝난 다음 달 반환으로 배치한다.
- `totalInflows12mKrw`에는 계약대금과 반환된 보증예치금, `totalOutflows12mKrw`에는 계약원가·기업 고정유출·보증예치가 포함되어 월별 순현금흐름과 같은 범위를 사용한다.
- `remainingReceivablesAfter12mKrw`는 12개월 안에 기성됐지만 그 이후 회수되는 금액, `remainingContractValueAfter12mKrw`는 미래 미이행분까지 포함한 전체 미회수 계약가액으로 구분한다. 팩토링 한도는 전자에만 80% 적격률을 적용한다.
- 필요자금은 `max(0, 유동성 버퍼 - 최저 예상 현금잔액)`이며 보증 준비금은 이미 최저 잔액에 반영된 제한성 현금이므로 신규 유동성 패키지 합계와 커버리지에서 제외한다.
- 금융 패키지의 선금·팩토링·운전자금 합계는 표시되는 총 유동성 조달액과 일치하고, 지급지연·금리 시나리오는 조달기간과 예상 금융비용에도 동일하게 적용한다.
- 동일한 비어 있지 않은 기업명의 계약은 포트폴리오 현금흐름에서 기업 현금·고정유출을 한 번만 반영한다. 이름이 없으면 동일 기업이라는 근거가 없으므로 계약별로 분리한다.
- 매출은 있지만 예상 총원가가 0원이면 유한한 손익분기 충격을 계산할 수 없다. 이때 수치는 시나리오 지원 상한인 200%로 표시하되 입력 검증 경고를 함께 반환한다.

## 상태와 개인정보

CSV로 반입한 워크스페이스는 브라우저 로컬 저장소에만 유지한다. 서버 영구저장소와 사용자 계정이 없는 현재 버전에서는 새로고침 후 작업을 이어갈 수 있지만 여러 기기 간 동기화되지 않는다. 공개 배포에서 민감한 실제 기업데이터를 사용할 때는 기관 승인 환경과 접근통제가 필요하다.

## 확장 지점

- KO-DLab 내부 기업키와 계약키 결합
- 실제 세금계산서·인보이스 기반 결제곡선
- 제품별 원가와 원자재지수 연결
- 정책금융 상품별 한도·보증 규칙 플러그인
- 승인된 데이터베이스와 조직별 인증

## 의도적으로 제외한 것

- 근거 없는 부도확률 또는 인과적 예방효과
- LLM이 계산·승인 여부를 직접 결정하는 흐름
- 브라우저에 공공데이터 인증키 전달
- 계약일을 현금 입금일로 간주하는 처리
