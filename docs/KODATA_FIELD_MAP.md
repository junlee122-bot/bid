# KODATA / KO-DLab 필드 맵

이 문서는 현재 BID SHIELD가 받는 기업 CSV 필드를 실제 코드의 사용처에 연결합니다. **KO-DLab의 실제 테이블·컬럼명은 아직 저장소에 포함되어 있지 않으므로**, 오른쪽의 “향후 후보”는 필요한 데이터 개념을 적은 것이며 제공 여부를 주장하지 않습니다. KO-DLab 접속 후 데이터 사전과 이용·반출 조건을 확인해 실제 컬럼명으로 치환해야 합니다.

## 1. 현재 CSV 스키마

- 금액 단위: 원(KRW)
- 필수 7개, 선택 9개
- 영문 표준명과 코드에 정의된 한국어 별칭 지원
- UTF-8 또는 CP949/EUC-KR, 최대 5MB·5,000행
- 서버는 요청 메모리에서 검증하며 CSV 파일을 디스크·DB에 저장하지 않음

| 현재 CSV 필드 | 필수 | 검증·품질 처리 | 현재 모델 활용 | 향후 KO-DLab 후보 개념 |
| --- | :---: | --- | --- | --- |
| `company_id` | 선택 | 문자열. 사업자번호가 없을 때 중복키·안정 기업키의 2순위 원천 | 포트폴리오 기업 그룹용 가명 `stableKey` 생성. 화면·분석 레코드에 원문 ID를 직접 저장하지 않음 | KODATA 기업 통합키, 기업 이력 연결키, 합병·분할 전후 관계 |
| `company_name` | **필수** | 비어 있으면 행 오류, 200자 초과 오류, 스프레드시트 수식 가능 문자열 경고 | 화면 표시, 이전 형식의 기업 그룹 대체키, 낙찰자명과 보수적 완전일치 비교 | 법인명·상호 이력, 표준화 기업명, 계열/관계기업 키 |
| `business_registration_no` | 선택 | 숫자 10자리 아니면 오류, 체크섬 불일치는 경고. 동일 번호·기준일 중복 거절 | 안정 기업키의 1순위 원천. 결합 후 원문 번호는 `ContractRecord` provenance에 보존하지 않음 | 가명 처리된 사업자키, 법인번호 연결키. 원문 식별자는 분석공간 내 최소권한 사용 |
| `industry_code` | 선택 | 문자열 | 계약의 업종 표시값. 없으면 사용자가 입력한 업종 라벨 사용 | 시점별 KSIC, 주·부업종, 산업위험·원가 인덱스 연결 |
| `credit_grade` | 선택 | 일반 기업등급 패턴 밖이면 경고 | 데이터 허브의 초기 연 이자율 제안: AAA/AA 5.2%, A 5.8%, BBB 6.6%, BB 7.6%, 그 외 9.2%. 현재 재무 provenance 스냅샷에는 보존하지 않음 | 등급·평가일·평가기관·등급전이·부도정의. 사용 권리와 등급 의미 확인 |
| `annual_revenue` | **필수** | 0 이상 숫자 | 월 운영현금유출 초기값(`연매출×4.5%÷12`, 최소 100만원), 부채/매출·수주잔고/매출 분모, 원가율 가정 설명의 영업이익률 계산 | 다기간 매출, 매출성장률, 변동성, 공공/민간 매출 비중 |
| `operating_profit` | **필수** | 숫자, 적자 음수 허용 | 현재 계약 원가를 직접 결정하지 않음. 결합 시 기업 영업이익률을 계산해 계약 원가율이 기업 전체 마진의 대용치일 뿐이라는 provenance 설명에 사용 | 다기간 영업이익·EBITDA, 이익률·변동성, 일회성 항목 |
| `cash_and_equivalents` | **필수** | 0 이상. 유동자산보다 크면 경고 | 계약 시작 가용현금, 계약·기업키별 12개월 현금흐름 시작점 | 월/분기 현금잔액, 제한성 예금, 미사용 약정한도, 실제 일별 잔액 |
| `current_assets` | **필수** | 0 이상. 현금보다 작으면 경고 | 유동비율과 순운전자본 계산, 필드 provenance, 데이터 품질 완전성 | 매출채권·재고·기타유동자산 세부, 연령분석, 담보·양도 여부 |
| `current_liabilities` | **필수** | 0 이상. 유동자산 초과 시 음수 운전자본 경고 | 유동비율과 순운전자본 계산. 유동비율은 부채부담 위험점수 일부와 100% 미만 경고 | 매입채무·단기차입·유동성장기부채·세금 세부와 만기일 |
| `total_debt` | **필수** | 0 이상. 연매출의 3배 초과 시 경고 | 명시값이 없을 때 기존 차입금 대용치, 월 상환액 초기값(`총부채×18%÷12`), 부채/매출 신호 | 차입상품별 잔액·금리·만기·상환일, 보증·담보, 미사용 한도 |
| `existing_order_backlog` | 선택 | 0 이상. 없으면 품질·분석 경고 | 수주잔고/매출 신호. 100% 초과 시 동시 이행부담 경고; 부채부담 위험점수 일부 | 계약별 잔여수주, 예상 수행월, 수익인식·취소·변경 이력 |
| `average_collection_days` | 선택 | 0~730일 | 데이터 허브의 지급지연 초기값(없으면 60일, 최종 15~180일 제한), 기업 신호 표시, 누락 경고 | 거래처·공공/민간별 회수일, 매출채권 aging, 실제 기성→청구→입금일 |
| `average_payment_days` | 선택 | 0~730일 | 기업 재무 신호와 provenance에 보존. 현재 현금흐름 지급시점·위험점수에는 직접 사용하지 않음 | 매입채무 aging, 공급자별 지급일, 원가 발생→지급 스케줄 |
| `employee_count` | 선택 | 0~10,000,000 정수 | 표시용 기업규모 추론: 10명 미만 micro, 50명 미만 small, 300명 미만 medium, 그 이상 large. 법령상 중소기업 분류가 아님 | 월별 고용, 직군, 현장 투입가능 인력, 이직·급여부담 |
| `as_of_date` | 선택 | 실제 존재하는 YYYY-MM-DD/YYYYMMDD/점·슬래시 형식 | 재무 provenance 기준일과 최신성 점수. 없으면 최신성 0점·오류, 365일 초과 경고 | 결산기준일과 입수·공시일 분리, 스냅샷 유효기간 |

### 코드상 필수와 품질상 기대는 다릅니다

CSV 수락에 필요한 필드는 7개지만, 구조화된 품질 완전성은 `as_of_date`, 수주잔고, 평균 회수·지급일, 조달 원문 URL과 필드 provenance도 확인합니다. 따라서 “업로드 성공”이 “실무 사용 준비 완료”를 의미하지 않습니다.

## 2. 현재 파생 신호

| 파생 신호 | 산식 | 현재 사용 | 0·누락 처리 |
| --- | --- | --- | --- |
| 영업이익률 | 영업이익 / 연매출 × 100 | 계약 원가율 가정의 한계를 설명하는 provenance 문구 | 연매출 0이면 `null` |
| 유동비율 | 유동자산 / 유동부채 × 100 | 화면, 100% 미만 경고, 부채부담 기여도 일부 | 유동부채 0이면 `null` |
| 순운전자본 | 유동자산 − 유동부채 | 화면·검토 신호 | 금액 차이 그대로, 현재 위험 가점 없음 |
| 부채/매출 | 총부채 / 연매출 × 100 | 화면, 부채부담 기여도 일부 | 연매출 0이면 `null` |
| 수주잔고/매출 | 기존 수주잔고 / 연매출 × 100 | 화면, 100% 초과 경고, 부채부담 기여도 일부 | 수주잔고 누락 또는 연매출 0이면 `null` |
| 기본 월 운영유출 | max(연매출×4.5%÷12, 100만원) | 조달 레코드 결합 UI의 수정 가능한 초기 가정 | 사용자가 실제 운영비로 교체 |
| 기본 월 채무상환 | 총부채×18%÷12 | 수정 가능한 초기 가정 | 총부채가 차입금·원리금 일정과 같지 않음을 경고 |
| 기본 지급지연 | clamp(평균 회수일 또는 60일, 15, 180) | 수정 가능한 초기 가정 | 계약서·기관 지급이력으로 교체 |

현재 원가율 초기값은 기업 영업이익률에서 자동 산출하지 않고 조달 업무별로 공사 92%, 용역 88%, 물품 90%를 제안합니다. 실제 계약 원가명세로 반드시 교체해야 합니다.

## 3. 조달 데이터와의 결합 맵

| 분석 필드 | 조달 우선순위 | 기업/사용자 보완 | provenance |
| --- | --- | --- | --- |
| 계약금액 | 낙찰금액 → 추정금액 | 사용자가 명시하면 최우선 | 조달 source 또는 user-assumption |
| 기초금액 | 기초금액 → 추정금액 → 계약금액 | 없음 | source |
| 계약일 | 계약일 → 개찰일 → 공고일 | 사용자 명시가 최우선 | source 또는 user-assumption |
| 발주처 | 수요기관 → 공고/계약기관 | 없으면 “기관명 미제공” | source |
| 낙찰률 | 상류 낙찰률 | 없으면 계약금액/기초금액 | source 또는 model-derived |
| 계약 원가 | 조달에서 제공하지 않음 | 사용자 확인 원가율×계약금액 | user-assumption + model-derived |
| 지급·보증·수행조건 | 현재 검색 API에서 충분하지 않음 | 사용자가 계약서 기준 입력 | user-assumption |

조달 생애주기는 `notice=opportunity`, `award=awarded`, `contract=contracted`입니다. 공고는 낙찰자 매칭 대상이 아니며, 낙찰·계약은 정규화 기업명과 낙찰자명을 완전일치 비교합니다. 불일치는 데이터 품질 오류와 계약 경고를 만듭니다.

## 4. KO-DLab에서 우선 확인할 추가 데이터

아래는 모델 검증 가치와 현재 결손을 기준으로 한 우선순위입니다.

| 우선 | 필요한 데이터 개념 | 연결키·시점 | 활용 목적 | 없을 때의 처리 |
| ---: | --- | --- | --- | --- |
| 1 | 계약별 기성·청구·실제 입금액/일 | 기업키+계약키+사건일 | 지급지연·월 유입·P90 coverage의 실제 검증 | 현 모델 가정 유지, 예측확률 주장 금지 |
| 2 | 계약별 실제 원가 발생·지급 | 기업키+계약키+월 | 원가곡선·생존마진·최대 자금공백 검증 | 사용자 원가율·곡선 사용 |
| 3 | 차입상품별 잔액·금리·상환일·한도 | 기업키+기준일 | 실제 이자·원리금·가용한도 반영 | 총부채 대용치와 수동 상환액 |
| 4 | 매출채권·매입채무 aging | 기업키+기준일 | 회수·지급 분포와 유동성 신호 | 평균 회수·지급일 |
| 5 | 계약변경·해지·중단·보증사고 | 계약키+사건일 | outcome 라벨과 사건 그래프 | 단순 계약 스냅샷, 라벨링 불가 |
| 6 | 다기간 재무제표와 입수가능일 | 기업키+결산일+입수일 | point-in-time 특징, 추세·변동성 | 단일 최신 스냅샷 |
| 7 | 수주잔고의 계약별 잔여액·수행월 | 기업키+계약키+월 | 동시이행부담과 자원제약 | 총액 비율 신호 |
| 8 | 등급·연체·부실 사건과 정의 | 기업키+평가/사건일 | 학습 라벨·보정·백테스트 | 확률모형 개발 보류 |
| 9 | 계열·공동수급·합병·분할 관계 | 관계키+유효기간 | 중복·전염·기업그룹 분할 방지 | 안정 기업키 단위만 분석 |
| 10 | 업종·품목별 원가/가격 지수 | 업종/품목+월 | 원가충격 분포의 외생 변수 | 공통 원가 가정 |

## 5. KO-DLab 반입 후 실제 매핑 절차

1. 데이터 사전에서 **테이블명, 컬럼명, 단위, 기준일, 입수일, 갱신주기, null 의미**를 확인합니다.
2. 현재 표의 개념마다 실제 컬럼을 0개·1개·복수로 매핑하고 변환식을 기록합니다.
3. 금액의 원/천원/백만원, 연결·별도재무, 누적·기간값, 부가세 포함 여부를 통일합니다.
4. 기업키·계약키·공고번호·차수·변경차수의 1:1/1:N 관계를 검사합니다.
5. 분석기준일 이후 값이 과거 특징에 섞이지 않도록 입수가능일 기준 point-in-time join을 구현합니다.
6. 원본→정제→파생 필드의 lineage와 행 수·누락·중복·제외 사유를 기록합니다.
7. 반출 가능한 것은 집계 통계·가명 결과로 제한하고 원문 식별자·민감정보는 분석공간 정책을 따릅니다.

## 6. 제안 ETL 계약

실제 컬럼명이 확인되면 아래와 같은 중간 스키마를 만들고 UI CSV와 같은 도메인으로 변환하는 방식을 권장합니다.

```text
company_snapshot
  stable_company_key
  financial_as_of_date
  available_from_date
  annual_revenue_krw
  operating_profit_krw
  cash_and_equivalents_krw
  current_assets_krw
  current_liabilities_krw
  total_debt_krw
  order_backlog_krw
  average_collection_days
  average_payment_days
  source_version

contract_event
  procurement_contract_key
  stable_company_key
  lifecycle_stage
  event_type
  occurred_at
  amount_krw
  source_version
```

이 이름들은 제안용 중간 스키마이며 KO-DLab 실제 컬럼명이 아닙니다.

## 7. 품질 수용 체크

- 기업·계약·기준일 키 중복과 null을 별도 집계
- 재무 기준일보다 입수가능일이 빠른 역전 0건
- 현금성자산 ≤ 유동자산 위반을 오류와 실제 회계 예외로 분리
- 수주잔고·회수일·지급일의 0과 null 의미 구분
- 낙찰자 불일치 건을 임의 연결하지 않고 격리
- 공고·낙찰·계약·변경 사건의 시간 역전 검사
- 금액 단위 변환 합계와 원천 집계 대조
- 모델 검증용 outcome의 사건일·정의·관측 종료 여부 보존
